# AGENTS.md

Operational instructions for **AI coding agents and automation** working in this repository.
This file is not user documentation — see [`README.md`](README.md) and [`docs/`](docs/README.md) for that.

## 1. What is product, what is workspace

| Path | Role | In git? |
| --- | --- | --- |
| `app/`, `ios/`, `agentcore/`, `agentd/`, `harness/` | Product source | yes |
| `spec/`, `fixtures/` | Cross-platform contracts and golden samples | yes |
| `docs/` | Human-facing documentation (architecture, i18n, changelog, audits, design records) | yes |
| `README.md`, `CONTRIBUTING.md`, `LICENSE` | Human-facing entry points | yes |
| `AGENTS.md` | This file — agent instructions | yes (declared as agent-facing) |
| `.tooling/` | Local JDK/SDK/Gradle caches used by automation | **no** |
| `dist/` | Built APKs copied out for the maintainer | **no** |
| `docs/screenshots/` | Verification screenshots | **no** |
| `*.build/`, `build/`, `.gradle/`, `.kotlin/` | Build outputs | **no** |
| `/tmp/...` evidence (logs, captures) | Throwaway verification artefacts | n/a |

Rules:

- Never commit anything from the "no" rows. If you produce evidence, write it under `/tmp/` and summarise it in the
  final report; do not move it into the repository.
- Do not add agent-only instructions to human docs (`README`, `CONTRIBUTING`, `docs/*`). Version-bump procedures,
  audit procedures, sub-agent scopes and workspace paths belong **here**.
- Do not add `TODO(agent)` / "generated by" / "as requested by the maintainer" notes to product code or docs.

## 2. Build and test (workspace paths)

Android / shared JVM:

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/amazon-corretto-17.jdk/Contents/Home
export ANDROID_HOME=$PWD/.tooling/android-sdk
export ANDROID_USER_HOME=$PWD/.tooling/android-user
export GRADLE_USER_HOME=$PWD/.tooling/build-home
export TMPDIR=$PWD/.tooling/tmp
.tooling/gradle-8.9/bin/gradle -p . :app:testDebugUnitTest :app:assembleDebug \
  :app:lintDebug :agentcore:test :agentd:test :agentd:build --console=plain
```

iOS:

```bash
cd ios/MyFriendKit && TMPDIR=$PWD/../.build/tmp \
  CLANG_MODULE_CACHE_PATH=$PWD/../.build/clang-cache \
  SWIFT_MODULE_CACHE_PATH=$PWD/../.build/swift-cache swift test --disable-sandbox

cd ios && TMPDIR=$PWD/.build/tmp CLANG_MODULE_CACHE_PATH=$PWD/.build/clang-cache \
  SWIFT_MODULE_CACHE_PATH=$PWD/.build/swift-cache xcodebuild -project MyFriend.xcodeproj \
  -scheme MyFriend -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath .build/DerivedData OTHER_SWIFT_FLAGS='$(inherited) -disable-sandbox' build
```

Public contributors use `./gradlew` and plain `swift test`; the paths above exist only in this workspace.

Simulators used for verification: Android AVD `MyFriendTest` (API 35, `com.myfriend.app.debug`), iOS `iPhone 17 Pro`
(`com.myfriend.app.ios`). Debug builds of the app may use `MYFRIEND_DEBUG_*` hooks; they are `#if DEBUG` only.

## 3. Version bump procedure

Scheme (maintainer-owned): beta series `0.x`; **small change** → last digit +1 (`0.11.1` → `0.11.2`);
**large change** (new capability surface, architecture or data-structure change) → middle digit +1 and last digit 0
(`0.11.2` → `0.12.0`); the major digit changes only when the maintainer explicitly says so.

A bump touches exactly these places, all in the same commit:

1. `app/build.gradle.kts` — `versionCode` (+1, never reused) and `versionName`.
2. `ios/MyFriend.xcodeproj/project.pbxproj` — `CURRENT_PROJECT_VERSION` (equal to `versionCode`) and
   `MARKETING_VERSION`, in **both** Debug and Release configurations.
3. `docs/CHANGELOG.md` and `docs/CHANGELOG.en.md` — a new `## <version>` section (plain past tense, no agent voice).
4. `README.md` / `README.en.md` — the status table (version + test counts).
5. Tag `v<version>` with the changelog section as the annotated-tag message and as the GitHub Release body
   (`prerelease: true` while the series is `0.x`), unless the maintainer asked for no tag.

`versionCode` / `CURRENT_PROJECT_VERSION` are decoupled from the database schema version: schema increments only when
tables or columns change (see §5).

## 4. Sub-agent / parallel work conventions

- Split by platform or by layer and record **disjoint write scopes**; never have two agents edit the same file.
- Human docs (`README*`, `CONTRIBUTING*`, `docs/*`) are owned by the coordinating agent, not by implementation agents.
- Do not run `git` commands from implementation agents; the coordinator commits.
- Every agent report must end with an honest "not done / risks" list.

## 5. Data & contract changes

| Change | Also required |
| --- | --- |
| Any table/column/index change | schema version +1, migration (`MIGRATION_n_n+1` on Android, `migrateLegacyData` on iOS), migration test, both platforms in the same change |
| Backup structure change | `backup.formatVersion` +1, `fixtures/backup/` regenerated, both `BackupFixtureTest` and `BackupInteropTests` updated |
| Agent-decision change | update `agentcore/`, `spec/agent-core/cases/*.json`, and the Swift implementation |
| Search semantics change | update `spec/search/cases/*.json` |
| New UI string | `values/strings.xml` **and** `values-en/strings.xml`; `zh-Hans.lproj` **and** `en.lproj` |

## 6. Audit procedure (agent-driven)

1. Request a **read-only** audit: "find defects, do not modify code".
2. The auditor writes exactly one file: `docs/audits/<version>-<scope>.md` (severity, `file:line`, trigger, why it is
   wrong, one-line fix, plus "checked and not a defect").
3. Findings are fixed with a test each; the fix commit quotes the finding id (`P1-3`).
4. Update `docs/audits/README.md`'s status table.

Human-facing explanation of the audit records lives in `docs/audits/README.md`; the process above does not belong there.

## 7. Definition of done

- All suites green: `:app:testDebugUnitTest`, `:agentcore:test`, `:agentd:test`, `swift test --disable-sandbox`.
- Builds: `:app:assembleDebug`, `:app:assembleRelease`, `:app:lintDebug`, `:agentd:build`, iOS Debug **and** Release,
  with zero Swift warnings.
- Docs updated in both languages where the change is user-visible.
- No workspace artefacts staged; `git status` contains only intended product/doc changes.
