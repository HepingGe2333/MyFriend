# 国际化（i18n）方案

> English version: [I18N.en.md](I18N.en.md)

YetAnotherPal（Yap）的界面语言为**中文（默认 / base）**与**英文**。语言跟随系统，不提供应用内语言开关；未匹配到英文的系统语言一律回落到中文。

## 语言选择

| 平台 | 机制 |
| --- | --- |
| Android | 基资源 `res/values/` 为中文；英文资源在 `res/values-en/`。系统语言为英语时使用 `values-en`，其它语言（如日语）回落 `values`。`AndroidManifest.xml` 通过 `android:localeConfig="@xml/locales_config"` 声明 `zh` / `en`，因此 Android 13+ 的系统「应用语言」设置里可以直接为 Yap 选择语言。没有 `resConfigs` 限制。 |
| iOS | `Bundle.main` 依据系统语言查找 `.lproj`。`ios/Config/Info.plist` 中 `CFBundleDevelopmentRegion = zh-Hans`，`CFBundleLocalizations = [zh-Hans, en]`；工程 `knownRegions` 含 `zh-Hans`、`en`、`Base`。iOS 13+ 的系统「设置 → Yap → 语言」同样可以单独指定。 |

两端都不实现应用内切换：语言属于设备环境，不属于人格设定。

## 资源位置

**Android**

```
app/src/main/res/
├── values/strings.xml            中文（base，默认）
├── values/seed.xml               种子人格文案（中文）
├── values-en/strings.xml         英文
├── values-en/seed.xml            种子人格文案（英文）
└── xml/locales_config.xml        zh / en 声明
```

`values-night/`、`values-v27/`、`values-night-v27/` 只包含颜色与主题，没有语言相关的字符串。

当前规模（以文件为准）：Android `strings.xml` 两套各 876 条（856 条 `<string>` + 20 条 `<plurals>`；中文 plurals 每条只有 `other`，英文每条有 `other`，部分另带 `one`），`seed.xml` 两套各 12 条（3 个人格 × name / description / category / prompt）；另有一个按语言取值的整数资源 `usage_tokens_compact_divisor`（中文 10000、英文 1000），以及 `common_clock_pattern` 一类日期/时间格式（中文 `HH:mm` / `M月d日`，英文 `h:mm a` / `MMM d`），它们不需要「翻译」，但必须两种语言都有。iOS 两份 `Localizable.strings` 各 557 条（541 个 key + 16 个英语 `.one` 变体），两份 `InfoPlist.strings` 各 1 条；SwiftUI 层约有 637 处本地化调用点。

**iOS**

```
ios/YetAnotherPal/Resources/
├── zh-Hans.lproj/Localizable.strings   中文（除语义 key 外，key 与 value 均为中文原文）
├── zh-Hans.lproj/InfoPlist.strings     系统权限弹窗文案
├── en.lproj/Localizable.strings        英文（key 与中文版完全相同）
└── en.lproj/InfoPlist.strings          英文权限弹窗文案
```

iOS 以**中文原文作为 key**（唯一的语义 key 是 `prompt_language_directive`，与 Android 的 `R.string.prompt_language_directive` 同名）。这样中文包天然是恒等映射，英文包只需给同一批 key 提供译文，也便于在代码里直接读懂 `NSLocalizedString("他发来一条消息", ...)` 的语义。

## 新增文案的规则

1. **一次改两份**：Android 同时改 `values/strings.xml` 与 `values-en/strings.xml`；iOS 同时改 `zh-Hans.lproj` 与 `en.lproj`。只加一份会在守卫测试里红。
2. **键集合与占位符一致**：同一 key 在两个语言文件中必须存在，且 `%1$s` / `%2$d` 一类占位符集合必须一致（不能少参数；英文可以调整顺序，但类型要对应），否则运行时格式化会崩。
3. **命名**：Android 使用 snake_case 加页面/组件前缀——`home_` / `chat_` / `search_` / `persona_` / `memory_` / `proactive_` / `evolution_` / `preset_` / `settings_` / `about_` / `api_` / `browser_` / `backup_` / `usage_` / `common_` / `seed_` / `prompt_`。iOS 的 key 是中文原文，不另设命名空间。
4. **UI 代码不写死文案**：界面层只引用资源。Android 用 `stringResource(R.string.…)` / `context.getString(…)`；iOS 用 `L()` / `Lf()` / `Lcount()`（定义在 `ios/YetAnotherPal/App/Localization.swift`，内部走 `NSLocalizedString`，`Lcount` 负责单复数变体）。
5. **应用代码中用户可见的文案**（通知标题与正文、设置页说明、错误提示、按钮、空状态）都必须进资源；面向模型的文案、日志、调试信息不进资源。

## 不翻译的内容

以下内容保持中文，**不**进入本地化资源：

- **代码注释**：注释解释设计取舍，读者是维护者；
- **日志与调试输出**（包括 `debug.log`、`[chat]` 日志、测试输出）；
- **模型提示词脚手架**：`ios/YapKit` 与 Android `domain/` 中的 system prompt 片段、工具描述、能力清单、记忆抽取与整理提示词、复盘/打分提示词；
- **数据契约**：JSON 字段名、工具名（`remember` / `recall` / `defer_reply` …）、枚举取值、Room / SQLite 的表名与列名、备份里的 `format` / `formatVersion`；
- **参考服务**：`harness/server.mjs` 的 mock 响应与日志；
- **测试代码**：测试名与断言消息。

原因：这些字符串是**协议与实现**的一部分，翻译会同时改变行为、测试与跨端契约，却没有给用户带来收益。除语言指令小节外，提示词脚手架不能按 UI 语言切换，否则两端模型行为会分叉。

## 模型语言：语言指令小节

模型的提示词脚手架不翻译，但模型必须能说用户的语言。做法是：两端在 system 提示词的**末尾**追加一个「语言指令」小节，内容要求模型用对方正在使用的语言回答。它是唯一与 UI 语言相关、又不属于普通界面文案的提示词片段。

| 平台 | 模板位置 | 语言 | 说明 |
| --- | --- | --- | --- |
| Android | `values/strings.xml` 与 `values-en/strings.xml` 的 `prompt_language_directive` | 随 UI 语言：中文界面追加 `## 语言` + 中文正文，英文界面追加 `## Language` + 英文正文 | 由 `LanguageDirective.section(…)` 拼装，在 `ChatRepository` 组 system 的最后一步追加；语言名由 `LanguageDirective.languageName()` 给出，只取语言不取地区（`zh-CN` → 「中文」，`en-US` → 「English」） |
| iOS | `Localizable.strings` 的语义 key `prompt_language_directive` | 随界面语言，模板文案与 Android 逐字一致 | 由 `AppLanguage.languageDirective` 取模板与语言名后交给 `PromptBuilder`；Kit 不读资源、不读 `Locale`，只负责拼装。占位符按 iOS 的 `String(format:)` 写成 `%1$@`（Android 是 `%1$s`），语义相同 |

两端模板文字逐字一致，只有占位符语法不同；**小节随界面语言本地化**是该提示词片段的特例。脚手架主体（工具描述、能力清单、记忆抽取与整理提示词等）仍保持中文。

其余约定：

- 小节固定在 system 末尾，便于测试断言「提示词以该小节收尾」；
- 这是**指令**而不是强约束：模型仍可能用错语言或中英混排，属于可接受误差，不做后处理改写；
- 对话语言与 UI 语言相互独立：用户可以在英文界面里用中文聊天，模型应当跟随**用户消息**的语言。

## 资源一致性守卫

| 平台 | 测试 | 断言 |
| --- | --- | --- |
| Android | `app/src/test/java/com/yap/app/i18n/StringResourceParityTest.kt` | `values` 与 `values-en` 的 string key 集合完全相等；同一 key 的占位符集合一致；复数形态按语言校验（中文只有 `other`，英文必须有 `other`，可多一个 `one`） |
| Android | `app/src/test/java/com/yap/app/i18n/ChineseLiteralGuardTest.kt` | `ui/`、`util/` 的 Kotlin 源码除注释、日志与白名单外，不允许出现中文字符串字面量 |
| Android | `app/src/test/java/com/yap/app/i18n/LanguageDirectiveTest.kt` | 中英两种语言下，system 提示词末尾都追加了语言指令小节 |
| iOS | `ios/YapKit/Tests/YapKitTests/I18N/LocalizationResourceTests.swift` | 两份 `Localizable.strings` 的 key 集合相等、无重复 key；同一 key 的占位符集合一致（允许英语调整顺序、不允许丢参数）；`.one` 变体成对出现；代码里 `L` / `Lf` / `Lcount` / `NSLocalizedString` 用到的 key 都能找到，资源里也没有死 key；`prompt_language_directive` 与 Android 逐字一致；两份 `InfoPlist.strings` 同步 |
| iOS | `ios/YapKit/Tests/YapKitTests/I18N/UIChineseLiteralGuardTests.swift` | `ios/YetAnotherPal/Views/**` 与 `ios/YetAnotherPal/App/**` 的中文只允许出现在注释、日志与显式白名单中 |

守卫测试与业务测试一起跑（`./gradlew :app:testDebugUnitTest`、`swift test --disable-sandbox`），没有单独的 i18n 流水线。

## 种子人格

首次安装时写入的种子人格按语言分两套：中文环境两端都是林深 / 阿岚 / 墨；英文环境使用英文原生人格，目前 Android 为 Elias / Finn / Ansel，iOS 为 Rowan / Juno / Ellis（人设文案由两端各自的 `SeedPersonas` 维护，不参与备份互通）。种子人格只在人格表为空且从未 seed 过时写入一次；之后切换系统语言不会重新 seed、不会改写已有人格，也不产生数据库迁移。语言只影响「第一次见面时长什么样」。

## 新增一门语言

1. Android：新增 `res/values-<locale>/strings.xml` 与 `seed.xml`，在 `res/xml/locales_config.xml` 里加上该 locale；`StringResourceParityTest` 的对比目标需要从「固定 en」改为遍历全部 `values-*` 目录（当前实现只保证 zh / en 一致）。
2. iOS：新增 `<locale>.lproj/Localizable.strings` 与 `InfoPlist.strings`，把 locale 加进 `CFBundleLocalizations` 与工程 `knownRegions`。
3. 语言指令小节的语言名需要在新语言下正确显示（由应用层提供显示名）。
4. 跑两端守卫测试与快照走查，确认没有混排或截断。

- **工具痕迹标题已本地化**（0.10.2）：显示用标题/副标题走资源，**模型面向的结果文本仍是中文**（`ToolResult.modelSummary`）；两端标题逐字一致，有 golden 测试与真机资源测试。

## 已知限制

- **没有应用内切换**：只能跟随系统或系统级「应用语言」设置。
- **英文是中文的译文**：文案以中文为准，英文版在语义上对齐，但不保证语气完全等效。
- **iOS 未使用 `stringsdict`**：复数用 `.one` 变体加普通占位符处理，不引入额外的格式文件；极端数量下英文措辞可能不够自然。
- **RTL 未验证**：目前没有阿拉伯语等从右到左语言。
- **长文案截断**：英文普遍比中文长，窄屏组件需要在英文下单独走查（这是切换语言后最常见的视觉回归）。
- **模型语言是指令级的**：见上文，不做输出后处理。
- **iOS Kit 的用户可见文案已英文化**（0.10.0 收尾补齐）：`String(localized:)` 以中文原文为 key，SPM 测试无资源时回落中文，
  App 内由 `zh-Hans` / `en` 两份 `Localizable.strings`（各 765 条）提供译文；覆盖 Presence、心情词、睡眠状态行、工具动作标题、
  备份/清空摘要、通知、记忆抽屉与网络错误。
- **0.10.1 起用「结构化错误」代替中文文案**：`data/` 与 `network/` 只抛 `UserError`（`Domain(code, arg, number)` /
  `Network(kind)`），UI 经 `ui/common/ErrorText.kt` 映射到资源；落库的 `messages.errorMessage`、
  `ToolTraceItem.detail`、`proactive_rules.lastError` 存 ASCII 令牌 `@mf-err:...` / `@rev:...`，渲染时按语言翻译。
  老库里的中文值原样显示（不改写、不加迁移）。`ChineseLiteralGuardTest` 已把 `data/` 与 `network/` 纳入扫描，
  只剩 18 个面向模型/落库的提示词文件在白名单里（每条写了理由）。
- **仍会看到中文的地方（两端）**：① 工具痕迹的**标题**（「联网搜索」「记住了」，来自 `ToolProtocol`）；② 模型写出的文本
  （心情理由、记忆正文、人格名/简介）与升级前已落库的数据；③ 提示词脚手架、代码注释与日志。
  因此**不能声称为「完全双语」**。
- **英文种子人设两端不同名**：Android 与 iOS 各自维护一套英文人设（名字见上文），只影响首次安装，不影响备份互通。
