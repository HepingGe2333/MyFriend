# 声音与视频模态（0.13 参考，未来目标）

> 本文件是**第 3 步的可选/未来目标**，不进入 0.13 实现范围；作为后续 feat 分支的实现参考。

## 目标

模型不只是「读转写文本」，而是能：
- **听音频**：把语音/环境音作为多模态输入发给支持音频的模型（如 Qwen-Omni / Gemini），
  理解语气、停顿、情绪，而不是只拿到 ASR 文本；
- **看视频**：把视频按关键帧 + 音轨切片，作为多模态输入理解画面与声音。

## 参考实现（DSH 插件）

DSH 的 `dsh-video-vision` 一类插件把视频拆成「关键帧序列 + 音轨转写」再交给多模态模型；
可参考其切片策略（场景变化检测、固定间隔、上限帧数）与降采样参数。

## 需要的改动

| 层 | 改动 |
| --- | --- |
| 数据 | `messages` 附件类型增加 `AUDIO`/`VIDEO`；媒体表存 mime/duration/宽高/关键帧数 |
| 提示词 | 多模态消息按 provider 能力拼装（OpenAI content parts / Gemini parts）；不支持时降级为「音频转写 + 视频关键帧描述」 |
| 工具 | `listen(audioId)` / `watch(videoId)` 让模型主动请求某段媒体；结果作为 tool result 回灌 |
| 客户端 | 录音/选视频、上传（服务端媒体）、播放器展示；压缩策略（音频 16k mono opus，视频 720p/关键帧） |
| 成本 | 音频/视频 token 昂贵：默认只在用户显式发送时处理，不主动扫描历史 |

## 风险

- 各家多模态 API 形状不同（OpenAI 只收图/音频片段，Gemini 收视频），需要 provider adapter；
- 隐私：录音/视频不出本机（服务端模式上传到自己的服务端）；
- 时长与大小上限（建议音频 ≤10 分钟、视频 ≤2 分钟/≤100 MiB），超限拒绝并提示。
