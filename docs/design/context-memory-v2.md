# 上下文与记忆 v2（0.15）

## 每轮上下文的固定结构（按顺序）

1. **完整设定**：身份/世界/关系/话风/边界；工具清单与「你能做什么」；
2. **长期记忆（缓存）**：跨越很多轮的稳定事实、约定、重要事件（≤500 字）；
3. **短期记忆（缓存）**：最近几轮定下的计划、待办、情绪线索（≤200 字）；
4. **当前状态**：时间/活动/睡眠/心情（直觉标签 + 三维）；
5. **对话主题总结**：按主题分段的滚动摘要（每段 ≤120 字，最多 12 段），带时间段；
6. **剩余预算**：窗口减去以上固定段后，全部用于最近聊天原文。

顺序固定、段标题固定；预算是硬约束（字符近似 2 字符/token），超出时先压缩主题总结，再减少历史条数。

## 长短期记忆只是缓存

- 真正的短期记忆 = 完整的会话上下文（原文），不靠摘要；
- 摘要只提示「前几步定下的规划/约定」，防止长对话丢失线索；
- 过去的细节通过**主题总结检索 + `memorize` 工具**取回：
  - 模型说「让我想想/让我回忆一下」→ 调用 `memorize(query)`；
  - 工具在**会话历史**里检索（关键词+主题段+时间衰减），返回「<回忆：某段时间的对话摘要 + 关键原句>」；
  - 注入到下一轮上下文（作为工具结果），并可显示一行「（他想了想）」。

## 更新节奏

- 短期缓存：每 5 轮或模型认为计划变化时更新（≤200 字）；
- 长期缓存：每 15–40 轮由模型根据上下文决定是否更新（≤500 字）；
- 主题总结：每 15–40 轮滚动更新，或话题明显切换时；
- 心情：**每条用户消息后重新判定一次**（直觉标签+三维），模型中途也可用 `set_mood` 手动再改；取消「每维变化≤2」的硬限制，仅做物理范围夹取。
