# 0.15 上下文工程 profile（经 Bench v2 搜索）

## 选择方法

用 `eval/context_search.py` 对 8 个维度做坐标下降 + 组合验证（12 个多轮场景、campus-chat、
5 样本；综合分 = 0.6×judge + 0.4×确定性，硬失败封顶 60）。详细报告：
`eval/reports/context-search-*.md`、`eval/reports/bench2-guidance-summary-*.md`。

## 采用的 profile（保守最优）

| 维度 | 选择 | 说明 |
| --- | --- | --- |
| 架构 | **state_first** | 状态/心情段放在人设之前（1 样本时领先，5 样本时 85.3 vs 当前 84.3，硬失败 23.3% vs 26.7%） |
| 引导 | **g12（有点防备，不轻易示弱）** | 仅在心情偏负/低唤醒（arousal < 2）时注入；正向/平静（arousal ≥ 2）用 g17（只聊此刻） |
| 记忆 | full（短期+长期+主题） | 保持不变 |
| 反 AI 规则 | **core（5 条）** | 保留：不反问/不总结/不列点/不总安慰/不旁白；删掉两条较弱的 |
| 工具段 | full | 保持不变 |
| 历史格式 | **timestamped** | `[HH:mm] 用户：…` / `[HH:mm] 他：…` |
| 状态段 | full（时间+活动+心情+引导） | 保持不变（minimal 的收益在噪声内，风险更大） |
| 人设段 | full（身份/世界/话风/关系） | 保持不变（compact 会丢世界/关系，过拟合风险） |

## 注入规则

- 心情负向（valence < 0）或唤醒度 < 2：引导 g12；
- 否则：引导 g17（只聊此刻，不翻旧账）；
- 两者都放在 `# 引导` 段，位于心情之后、话风之前。
- 历史时间戳取消息 `createdAt` 的本地 HH:mm；跨天加日期。
- 反 AI 五条逐字固定，不再由各端各写一套。

## 验收

- 两端与服务端的段顺序一致：状态（含心情/引导）→ 人设 → 工具 → 反AI → 记忆 → 语言 → 边界；
- g12/g17 按心情选择，有契约测试；
- 历史时间戳格式一致，跨天正确；
- Bench v2 回归不低于当前 profile（允许 ±2 分噪声）。
