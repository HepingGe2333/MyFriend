# Search conformance contract

Language-neutral cases that keep **chat-history search** identical on Android and iOS.

Two files, both consumed by a test on each platform:

| File | Covers | Generated by |
| --- | --- | --- |
| `cases/snippet.json` | the pure snippet / highlight function (no DB, no I/O) | hand-written to the rules below |
| `cases/ranking.json` | ordering of hits for a query | generated by the Android implementation, then asserted by iOS |

## Snippet rules (normative)

Given `content` (message text), `query` (already trimmed) and `window = 60`:

1. `query` empty → `text = ""`, `highlights = []`.
2. Find the first case-insensitive occurrence of `query` in `content`.
3. If there is **no** match: `text` is the first `window` characters of `content` plus `"…"` when truncated; `highlights = []`.
4. If there **is** a match at `index`:
   - `start = max(0, index - 30)`, `end = min(content.length, start + window)`;
   - if `start > 0 && end - start < window` then `start = max(0, end - window)`;
   - `text = ("…" if start > 0 else "") + content[start:end] + ("…" if end < content.length else "")`.
5. `highlights` are **all** case-insensitive occurrences of `query` inside `content[start:end]`, as `[startOffset, endOffset)` pairs relative to the returned `text` (i.e. offset by the length of the leading `"…"`).

Characters are counted in UTF-16 code units (Kotlin `String` / Swift `String.Index` semantics on BMP text). The cases avoid emoji so both languages agree.

## Ranking rules (normative)

- A message is a hit when `content` matches `query` case-insensitively, **or** any term produced by the shared `ChineseTerms` tokenizer matches.
- Score: the number of distinct query terms matched (descending), then the shared `ChineseTerms.relevance(query, content)` (descending).
- Tie-break: `createdAt` descending, then `id` ascending (stable and platform-independent).
- `cases/ranking.json` records the resulting order as `expectOrder` (array of message ids). Android generates it; iOS must reproduce it. If a behaviour change reorders hits, **both** platforms must be updated together — that is the point of the file.

## Filters (normative)

`personaId` (null = every persona) and `since` (null = all time) filter the candidate set *before* ranking. `cases/ranking.json` may include `filter` objects; platforms must apply them identically.

## Adding cases

Append to the JSON array, keep the existing keys (`name`, `input`, `expect`, optional `why`), and run both test suites:

```bash
./gradlew :app:testDebugUnitTest --tests '*SearchSpecTest*'
cd ios/MyFriendKit && swift test --disable-sandbox --filter SearchSpecTests
```
